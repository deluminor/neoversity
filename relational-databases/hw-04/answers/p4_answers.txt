4.2 What happens when some INNER JOINs are replaced with LEFT / RIGHT JOIN?
Observed counts on this dataset:
- INNER JOIN (all tables): 518
- LEFT JOIN customers (rest INNER): 518
- RIGHT JOIN shippers (rest INNER): 518

Why the count did not change:
Every foreign key in the Topic 3 dump has a matching parent row
(order_details → orders → customers/employees/shippers, products → categories/suppliers).
LEFT / RIGHT JOIN keep unmatched rows from the preserved side, but here there are
no unmatched keys, so the result size stays the same as INNER JOIN.

When the count would grow or shrink:
- LEFT JOIN can keep more rows if the left table has keys missing on the right
  (those rows appear with NULL columns from the right table).
- RIGHT JOIN can keep more rows if the right table has keys missing on the left.
- If later INNER JOINs are still present, they can remove those NULL-extended rows
  again — that is why changing only one join does not always change COUNT(*).
